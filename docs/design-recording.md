## 1. 需求(用户原话拆解)

| # | 需求 | 决策 |
|---|---|---|
| R1 | 录音功能,m4a 格式 | MediaRecorder,AAC/44.1kHz/mono/128kbps |
| R2 | 录音过程支持暂停/继续 | `MediaRecorder.pause()/resume()`(API 24+),计时排除暂停段 |
| R3 | 录音后可分享到微信 | FileProvider + `ACTION_SEND`,系统分享面板;微信以文件形式接收,**不引入微信 SDK** |

| R5 | **严格测试,不能破坏当前播放所有功能**(2026-11-10 补充) | 见 §6 隔离约束与回归矩阵 |
| R6 | 布局采用方案 A(已拍板) | 「录音」进 chips 行,列表复用现有播放条 |

## 2. UI 设计(方案 A + 悬浮键修订)

### 2.1 主界面(录音视图)

```
┌──────────────────────────────────────┐
│ HiRust Player v0.10.0         [⚙]    │
├──────────────────────────────────────┤
│ [全部音乐][我的音乐][录音][＋文件夹]  │
├──────────────────────────────────────┤
│ ┌────┐ REC 20261110_1030     0:35   │
│ │ ▶  │                      [分享]  │ ← 行内分享(仅录音视图)
│ └────┘                               │
│ ┌────┐ REC 20261109_0812     1:12   │
│ │    │                      [分享]  │
│ └────┘                               │
│              ⋮                       │
│         ──────●──────────            │ ← 现有播放条(不变)
│  [⏮] [⏸ 暂停] [⏭]           [1.0×]  │
│ [顺序] [随机·关] 音量 ────●───        │
│                          (🎤)       │ ← 悬浮录音 FAB(所有视图
└──────────────────────────────────────┘    均显示,右下角)
```

### 2.2 录音中覆盖层(全屏,拦截所有交互)

```
┌──────────────────────────────────────┐
│         (半透明遮罩)                 │
│            ● 录音中   00:42           │
│                                      │
│    ┃┃┃┃┃ ┃┃ ┃┃┃┃┃┃ ┃┃┃ (电平条,     │
│      24 根,100ms 刷新,滚动历史)      │
│                                      │
│        [ ⏸ 暂停 / ▶ 继续 ]           │
│        [ ⏹ 停止并保存 ]              │
└──────────────────────────────────────┘
```

- 暂停态:标题变「已暂停」,电平条静止
- 停止:<1s 判误触丢弃(Toast);否则保存 → 回到录音视图并刷新(新录音置顶)

### 2.3 分享流

点行内 [分享] → `Intent.createChooser(ACTION_SEND, audio/mp4)` → 系统面板选微信 → 好友/收藏。微信以文件形式接收(其原生行为,音频可直接试听)。

## 3. 架构设计

### 3.1 组件与数据流

```
Recorder.kt(新增,唯一状态源)
  ├─ MediaRecorder(生命周期: start→pause/resume→stop/release)
  ├─ 心跳线程(100ms): elapsedMs 累计(排除暂停段) + maxAmplitude
  ├─ StateFlow<State> ──────────→ UI 覆盖层(计时/电平/按钮)
  └─ share(ctx, path): FileProvider URI → 系统分享面板

录音列表(复用既有视图/队列管线,零新概念):
  Recorder.dir = getExternalFilesDir/Recordings   (应用专属,MediaStore 不索引)
  列表条目 = 目录 m4a 枚举(按修改时间倒序)+ Rust trackInfo 补时长
  视图 source = Recordings 目录绝对路径
  点播走 PlayerBus.playFromView → 引擎照常解码(symphonia isomp4+aac 已支持)
```

### 3.2 状态机

```
Idle ──start()──▶ Recording(running)◀─resume()─┐
 ▲                    │                          │
 │               pause()                    Paused
 │                    ▶──────────────────────────┘
 └──────stop()───────┘(running 段计入累计)
 停止: stopped==成功 且 累计≥1s → 保存;否则删文件并置「过短已丢弃」
```

- 计时:`accumulatedMs(已完结段)+ (elapsedRealtime - segmentStart)(当前段)`
- 心跳线程 daemon,stop() 中 interrupt;MediaRecorder 任何调用失败 → 释放 + StateFlow.error,不抛出到 UI 层

### 3.3 与播放系统的关系(关键:零耦合)

| 关注点 | 设计 |
|---|---|
| 引擎/JNI | **零改动**;m4a 是引擎已支持格式(mp3/aac/isomp4 特性,M6 已修) |
| 播放服务/会话 | **零改动**;录音文件就是普通路径,入队即播 |
| 录音与播放并行 | 互不冲突:MediaRecorder 占麦克风,AudioTrack 走输出;录音中可照常播放/暂停既有队列 |
| 「全部音乐」视图 | 专属目录不被 MediaStore 索引 → 永不出现系统音乐 |
| 播放记录(0.9.0) | 录音列表 source 天然参与 persist/restore;restoreLastView 增加一个分支:source==Recordings 路径 → 打开录音视图 |
| 音频焦点 | 录音不申请焦点(只采集不外放);播放侧焦点逻辑不受影响 |

### 3.4 权限

- `RECORD_AUDIO` 运行时请求:首次点悬浮键时请求;拒绝 → Toast 提示,不进入录音态
- 已授权后续直接开始;设置中永久拒绝 → 引导语提示

## 4. 数据与持久化

- 文件:`REC_yyyyMMdd_HHmmss.m4a`(单声道 AAC,~0.5MB/分钟)
- 列表顺序:修改时间倒序(新录音置顶);标题=文件名去扩展名
- 无独立数据库:目录即数据源;删除文件=删除条目(v1 不做删除 UI,可后续加)

## 5. 已拍板决策记录

| # | 决策 | 备选与理由 |
|---|---|---|
| D-R1 | m4a/AAC | wav 每分钟 ~10MB,分享慢;AAC 微信兼容好 |
| D-R2 | 方案 A 轻量集成 | 独立页多一层导航且需重复做迷你播放控制 |
| D-R3 | 系统分享面板,不用微信 SDK | SDK 需 appId/审核,文件分享系统面板即可达 |
| D-R4 | 悬浮 FAB 全局可见(修订) | 原设计仅录音视图内显示;按用户 2026-11-10 要求改为全局悬浮 |
| D-R5 | 应用专属外部目录 | 公共 Music 目录会被 MediaStore 索引,污染「全部音乐」 |
| D-R6 | 过短(<1s)自动丢弃 | 防 FAB 误触产生空文件 |
